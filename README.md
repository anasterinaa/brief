# Сайт-бриф

Пошаговая анкета для клиентов: HTML + CSS + JS, без фреймворков и сборщиков.
Ответы уходят в Telegram сообщениями (через Cloudflare Worker).

## Что где лежит

| Файл | Зачем |
|---|---|
| `index.html` | разметка |
| `styles.css` | оформление и адаптив |
| `app.js` | логика; **вопросы, этапы и ваши контакты — в начале файла** |
| `config.js` | только адрес приёмника (Worker) |
| `worker.js` | код для Cloudflare — на сайт загружать не нужно |
| `photo.jpg` | ваша фотография для финального экрана (положите рядом с `index.html`) |

## Что заменить перед публикацией

В начале `app.js`, объект `SITE`:

- `telegram` — ваш ник без `@` (сейчас `your_username`);
- `legal` — ссылки на политику конфиденциальности, согласие, оферту и реквизиты (сейчас `#`);
- `requisites` — строка с реквизитами ИП для подвала;
- `replyDays` — за сколько рабочих дней вы отвечаете;
- `photo` — путь к фотографии (по умолчанию `photo.jpg`).

## Как подключить Telegram

1. **Бот.** В Telegram откройте `@BotFather` → `/newbot` → придумайте имя → скопируйте токен.
2. **Чат.** Напишите своему боту любое сообщение. Затем откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": …}` — это ваш `CHAT_ID`.
   (Чтобы брифы приходили в группу — добавьте бота в группу, напишите там и возьмите id группы.)
3. **Worker.** На [dash.cloudflare.com](https://dash.cloudflare.com) → Workers & Pages → Create → Hello World →
   Edit code → вставьте содержимое `worker.js` → Deploy.
4. **Переменные.** Worker → Settings → Variables and Secrets:
   - `BOT_TOKEN` (тип Secret) — токен бота;
   - `CHAT_ID` — id чата;
   - `ALLOWED_ORIGIN` (по желанию) — адрес сайта, например `https://username.github.io`.
5. **Адрес.** Скопируйте адрес Worker (`https://….workers.dev`) и вставьте в `config.js`:
   ```js
   window.BRIEF_CONFIG = { endpoint: "https://….workers.dev" };
   ```

Пока `endpoint` пустой, форма работает без отправки: в конце человеку скачивается файл с ответами.

## Как приходят ответы

- Первое сообщение — сводка: имя, компания, контакт и главное по делу (вопросы с `summary: true`).
- Дальше — каждый этап отдельным сообщением, вопросы жирным.
- Пустые ответы не показываются.
- Длинные блоки режутся по абзацам, лимит Telegram 4096 символов соблюдается.
- Файлы приходят отдельными документами (лимит бота Telegram — 50 МБ на файл, у нас 18 МБ).

## Как не потерять ответы

- Черновик сохраняется в браузере после каждого изменения. Файлы в браузере не хранятся — после перезагрузки их нужно прикрепить заново (сайт об этом напомнит).
- При любой ошибке отправки файл с ответами скачивается автоматически, черновик остаётся.
- Согласие на обработку данных после восстановления черновика ставится заново — это сделано намеренно.

## Как менять вопросы

Массив `QUESTIONS` в начале `app.js`. У каждого вопроса:

```js
{ id: "goal-why",        // уникальный id поля
  key: "goal_why",       // ключ ответа
  stage: 1,              // номер этапа из STAGES
  type: "text",          // textarea (по умолчанию) | text | links | files | consent
  label: "Текст вопроса",
  hint: "Пояснение под вопросом",
  required: true,        // обязательное
  important: true,       // плашка «важно»
  summary: true,         // попадёт в первое сообщение-сводку
  placeholder: "Серая подсказка в поле" }
```

Названия и описания этапов — массив `STAGES` там же. Добавили этап — счётчик, точки и прогресс-бар подстроятся сами.
Лимиты файлов — константы `MAX_FILES` и `MAX_FILE_MB`.

## Публикация на GitHub Pages

Загрузите содержимое папки (без `worker.js`, он не нужен) в репозиторий →
Settings → Pages → Branch: `main`, папка `/` (или `/brief`, если лежит в подпапке).

## Проверка локально

```bash
python3 -m http.server 8000
```
и откройте `http://localhost:8000/brief/`.
